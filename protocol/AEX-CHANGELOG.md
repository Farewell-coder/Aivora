# AEX Changelog

协议版本独立于 Aivora 应用版本演进。此处只记录**协议规范**的变更，应用更新日志见 [README 更新日志](../README.md#更新日志)。

## 1.0 — 已定稿（Aivora 0.0.5 起实现）

首个正式版本，Aivora 0.0.5 起实现。

- 确立 `.akcp` 作为唯一标准交换文件格式，MIME `application/vnd.aivora.akcp`。
- 容器结构：8 字节 Magic + 4 字节头部长度 + JSON 头部 + AES-256-GCM 密文。
- 加密方案：AES-256-GCM + PBKDF2-HMAC-SHA256，600000 次迭代，16 字节 Salt，12 字节 Nonce，128 位认证标签。
- 头部整体作为 AAD，防止协议版本与加密参数被篡改。
- Payload 采用 `profiles` 数组，统一承载单个、多个与全量配置。
- 定义 9 个错误码与四级兼容识别规则。

### 1.0 定稿决定

- 头部采用 JSON 序列化（非紧凑二进制），便于第三方解析与扩展。
- PBKDF2 迭代次数固定为 600000，接收方合法范围 100000–2000000。
- `apiKey` 允许为空串；`extra` 允许嵌套对象。
- 1.0 不包含发布方签名，完整性仅由 AES-GCM 认证标签保证。
- Aivora 0.0.5 起实现，导入导出双向单元测试通过。

## 1.0 补充说明（实现期）

- 导出提供“导出”（保存到本地）与“分享”（系统分享面板）两个入口，生成的文件字节一致。
- 明确凭证与文件分离：文件不携带凭证，接收方必须另行获得 52 字符凭证才能解密。
