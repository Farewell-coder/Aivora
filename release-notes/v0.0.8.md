# v0.0.8 · 深链导出与 AEX 1.1

这一版加了一条新的配置传递方式，并把协议升到 1.1。**这是一个不兼容的协议版本**，请先读完下面第二段再升级。

## 新增：深链导出

导出弹窗里多了一颗「深链」按钮，只在**单条配置**导出时出现。

- 点它 → 检查系统里有没有能接收的软件 → 有就弹一个纯名称列表
- 选中某个软件 → 直接跳过去，Aivora 自己退到后台
- 没有可用软件 → 提示「暂无支持深链传递的软件」

它传的是一条链接，不是文件：

| | `.akcp` 文件 | 深链 |
|---|---|---|
| 加密 | 需要凭证 | 明文，无凭证 |
| 记录 | 写导出记录 | 不记录 |
| 数量 | 单个或多个 | 仅单个 |
| 传递 | 微信、网盘、存本地 | 直达目标软件 |

因为不加密，界面里明确标注了这一点，链接也**不会**复制到剪贴板、不会写文件、不会进日志。

首批支持：**Dollhouse**。接入方式见新文档 [`protocol/AEX-DEEPLINK.md`](../protocol/AEX-DEEPLINK.md)。想加自己的软件，提 Issue 登记 scheme 与 host 即可，代码里只需加一行。

## 变更：AEX 1.1，导出不再带模型列表

`.akcp` 文件与深链都**不再包含 `models` 和 `defaultModel`**。

之前的做法是把导出那一瞬间的模型清单打包进去，问题有两个：模型随时上下线，快照很快就过期；各软件的模型命名规则不同，照搬过去反而是脏数据。

1.1 改成：接收方拿到 Endpoint 和 API Key 后，自己请求 `GET {baseUrl}/models` 现取现用。请求失败也不阻断导入，模型留空让用户手动加。

### 不兼容提醒

协议号是**精确匹配**，所以：

- 升级到 0.0.8 后，**此前导出的 1.0 版 `.akcp` 无法导入**，会提示「该文件由更新版本生成，请升级应用后再导入」
- 反过来，0.0.7 也读不了 0.0.8 导出的文件

这是移除字段的必然代价。如果需要保留旧文件，请先用旧版本导入导出为新格式，或直接重新导出一次。

## 修复：分享被误判为「没有可接收分享的应用」

上一版存在一个问题：点「分享」或导出记录里的「重新分享」时，可能直接提示「没有可接收分享的应用」而无法继续。

原因在 Android 11+ 的包可见性限制。应用要探测「系统里有哪些服务能接收这个文件」，必须先在自己的清单里声明它想查询的目标，否则系统一律回答「一个都没有」。之前只声明了深链的 scheme，漏了 `.akcp` 的 MIME 类型，于是这个探测在这类系统上始终返回空。

改动两处：

- 清单里补上 `.akcp` MIME 的查询声明
- 分享按钮不再用预检结果拦截。`ACTION_SEND` 的实际接收方包含系统「保存到文件」、蓝牙、邮件、网盘等，本来就没法穷举，预检天然不可靠。现在改为直接调起系统选择器，真的没有接收方时系统会明确报错，再提示用户

## 技术细节

- 协议版本 `PROTOCOL_VERSION` 由 `1.0` 改为 `1.1`
- 新增 `AexDeepLink`：接收方注册表 + 链接构造 + 投递，新增软件只需在注册表加一条
- `AndroidManifest.xml` 增加 `<queries>` 声明，否则 Android 11+ 的包可见性限制会让「有没有装 Dollhouse」永远判断为没有
- `AexTest` 新增两项：导出不含模型字段、1.0 容器被拒
- 新增 `AexDeepLinkTest`：6 项纯逻辑测试（JSON 字段、base64 无填充、链接拼装、注册表）

## 数据安全

- 深链全程不落盘、不进剪贴板、不记日志、不写导出记录
- `.akcp` 的加密参数完全未变：AES-256-GCM + PBKDF2-HMAC-SHA256 600000 次迭代
- 版本号变化不影响已有的配置库、导出记录、备份文件
